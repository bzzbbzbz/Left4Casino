# Ограбление Банка — Спецификация

## Обзор

**Ограбление Банка** — ежедневный ивент, во время которого все спины слотов наполняют общий банк (котёл). Когда ивент внезапно заканчивается, последний игрок, крутивший слоты, забирает весь банк за вычетом комиссии крупье. Длительность ивента скрыта от игроков. Масштаб банка адаптируется к экономике каждого чата.

---

## Базовая Величина (B)

Все экономические параметры ивента рассчитываются относительно **B** — суммы всех выигрышей в слотах данного чата за вчера.

### Расчёт B

```
B_raw = SUM(amount) FROM event_history
        WHERE chat_id = текущий чат
        AND event_type IN ('win', 'happy_moment_win', 'dice_challenge_win')
        AND amount > 0
        AND created_at IN вчерашний день (00:00-23:59 по таймзоне)
```

**Шум:** к B_raw применяется случайный коэффициент ×0.85–1.15 (±15%), чтобы игроки не могли вычислить точное значение по вчерашнему отчёту:

```
B = B_raw × uniform(0.85, 1.15)
```

**Исключения из B:** выигрыши самого ивента (`heist_win`) НЕ входят в расчёт B. Это предотвращает положительную обратную связь (большая выплата сегодня → больший банк завтра → ...).

**Fallback:** если B < 1000 (новый чат, мёртвый день) → B = 1000.

B рассчитывается **один раз** при старте ивента и не меняется в процессе.

---

## Экономические параметры

Все значения — процент от B:

| Параметр | Формула | Описание |
|----------|---------|----------|
| **pot_cap** | B × 5% | Макс. размер банка → досрочная Фаза 2 |
| **min_pot** | B × 1% | Мин. банк для завершения без продления |
| **seed** | B × random(0.5-1.5%) | Начальный взнос крупье (при отсутствии активности) |
| **commission** | % от банка (настр.) | Доля крупье (уничтожается из экономики) |

### Примеры масштабирования

| B (вчерашние выигрыши) | pot_cap (5%) | min_pot (1%) | seed (0.5-1.5%) | Макс. выплата (85%) |
|------------------------|--------------|--------------|-----------------|---------------------|
| 1 000 (fallback) | 50 | 10 | 5-15 | **42** |
| 5 000 | 250 | 50 | 25-75 | **212** |
| 50 000 | 2 500 | 500 | 250-750 | **2 125** |
| 500 000 | 25 000 | 5 000 | 2 500-7 500 | **21 250** |
| 1 000 000 | 50 000 | 10 000 | 5 000-15 000 | **42 500** |

Макс. выплата = **4.25% от B** = 4.25% от вчерашних выигрышей всего чата (при commission=15%).

### Инфляция

**НОВАЯ ЭКОНОМИКА (дефляционная модель):**

Банк состоит только из проигрышей игроков — реальных ставок, списанных с балансов.

В среднем ~53% спинов — проигрыши, ~47% — выигрыши (с учётом super jackpot).

| Метрика | Формула | При B=50000 |
|---------|---------|-------------|
| Макс. банк | B × 5% | 2 500 |
| Источник банка | Только проигрыши | 100% реальные ставки |
| Выплата (85% при commission=15%) | банк × 0.85 | 2 125 |
| Комиссия крупье (15%) | банк × 0.15 | 375 |
| Чистая инфляция | 0 | 0 |

**Чистая инфляция за ивент: 0%** — дефляционная модель. Деньги только перераспределяются между игроками. Комиссия крупье уничтожается из экономики.

## Двухфазная адаптивная длительность

Ключевой принцип: **чем быстрее растёт банк, тем быстрее заканчивается ивент**.

```
⏰ ПРЕДУПРЕЖДЕНИЕ (за 10 мин до старта)
│   └── Крупье: "Через 10 минут начнётся ограбление! Готовьте фишки!"
│
🏦 EVENT START (случайное время в активные часы, 1 раз в сутки)
│
├── Фаза 1: "ОГРАБЛЕНИЕ" (10-25 мин, случайно)
│   │
│   ├── Если pot = 0 после 5 мин → seed (B × random(5-10%))
│   │   └── Крупье: "Никто? Достаю из кармана {seed} очков!"
│   │
│   ├── Если pot ≥ pot_cap (B × 50%) → ДОСРОЧНЫЙ переход в Фазу 2
│   │
│   └── Таймер Фазы 1 истёк:
│       ├── pot < min_pot (B × 10%) → продлить Фазу 1 на +5 мин (однократно)
│       └── pot ≥ min_pot → переход в Фазу 2
│
├── Фаза 2: "ТРЕВОГА" (2-5 мин, случайно)
│   └── Таймер истёк → КОНЕЦ ИВЕНТА
│
└── Hard cap: 30 мин максимум (независимо от фаз)
```

### Самобалансировка: три сценария (B=50000)

**Тихий чат (3 игрока, bid=50, B=50000):**
- pot_cap = 2500
- Фаза 1: 20 мин, ~300 спинов, ~53% проигрышей = ~160 проигрышей
- Банк: 160 × 50 = 8000 очков (проигрыши)
- Выигрыши: ~140 × 50 × avg_mult ≈ 9800 очков (игрокам)
- pot_cap пробит → Фаза 2
- Выплата: 8000 × 0.85 = **6 800**
- Длительность: **~20 мин**

**Активный чат (8 игроков, avg bid=200, B=50000):**
- pot_cap = 2500
- Достигается за ~10-12 минут → Фаза 2 досрочно
- Фаза 2: 3 мин → банк ~3000
- Выплата: 3000 × 0.85 = **2 550**
- Длительность: **~13 мин**

**Кит (1 игрок, bid=10000, B=50000):**
- pot_cap = 2500
- Нужно ~1 проигрыш для достижения pot_cap (если проиграет первый спин)
- Если выигрывает — банк не растёт, кит получает выигрыш
- Киту выгодно играть! Может выиграть банк с минимальными вложениями
- Длительность: зависит от везения

## Механика спинов во время ивента

### Модификация обработки 🎰

Во время ивента каждый спин обрабатывается **по-особому** (per-chat):

```
Обычный режим:
  Проигрыш: balance -= bid
  Выигрыш:  balance += base × bid × jackpot × happy_moment

Режим ивента (НОВАЯ ЛОГИКА):
  Проигрыш: balance -= bid, pot += bid    (ставка списывается и идёт в банк)
  Выигрыш:  balance += calculated_win      (игрок получает выигрыш как обычно)
            pot не изменяется              (банк НЕ пополняется)
```

### Что учитывается при расчёте выигрыша

- ✅ base score (7, 5, 10 в зависимости от комбинации)
- ✅ bid (множитель ставки)
- ✅ super jackpot (x2, x3, x5, x10)
- ✅ happy moment (если активен одновременно)
- Итого: `calculated_win = base × bid × jackpot_mult × happy_moment_mult`

### Ограничения

- ❌ Игрок с balance ≤ 0 **не может** участвовать (удаление сообщения, как обычно)
- ❌ Если balance < bid — не может крутить (как обычно)
- ✅ Сейф (`/safe`) работает как обычно
- ✅ Дуэли (`/dice`) работают как обычно
- ✅ Переводы (`/give`) работают как обычно
- ✅ Обычные throttle-правила (2 сек для спинов)

### Отслеживание последнего игрока

При каждом спине во время ивента обновляется `last_spinner`:

```python
heist.last_spinner_id = user_id
heist.last_spinner_nickname = nickname
heist.last_spin_time = now()
```

Если на момент завершения ивента `last_spinner_id` отсутствует (никто не крутил) — ивент завершается без выплаты.

## Расписание

### Генерация времени запуска

- **Количество в сутки:** 1
- **Только активные часы:** ивент запускается строго в пределах `active_hours_start`–`active_hours_end` (по умолчанию 08:00–02:00). Ночью ивент **никогда** не происходит.
- **Таймзона:** из конфига `reports.timezone`
- Генерация в 00:00 или при старте бота
- Время выбирается случайно в пределах активного окна, с запасом `phase1_max_minutes + phase2_max_minutes + 10` от конца окна (чтобы ивент гарантированно завершился в активные часы)

```
Пример (active_hours 08:00–02:00):
  Запас = 25 + 5 + 10 = 40 мин
  Допустимый диапазон: 08:00 – 01:20
  Случайное время: uniform(08:00, 01:20)
```

### Предупреждение за 10 минут

За 10 минут до старта ивента бот отправляет оповещение во все чаты:

```
⏰🏦 ВНИМАНИЕ!

Через 10 минут начнётся Ограбление Банка!
Готовьте свои фишки — последний заберёт ВСЁ! 💰
```

Предупреждение планируется вместе с ивентом в планировщике (start_time - 10 мин).

### Генерация длительности

При старте ивента генерируются:

```
phase1_duration = random(10, 25) мин  — основная фаза
phase2_duration = random(2, 5) мин    — фаза тревоги
```

Оба значения скрыты от игроков.

```

```

```python
            await message.reply(
                f"🏦 Ваша ставка ({user_bid}) и выигрыш ({int(calculated_win)}) "
                f"ушли в банк ограбления!\n"
                f"💰 В банке: {result['pot']}\n"
                f"💳 Ваш баланс: {new_balance}"
            )
        else:
            await message.reply(
                f"🏦 Ставка ({user_bid}) ушла в банк ограбления.\n"
                f"💰 В банке: {result['pot']}\n"
                f"💳 Ваш баланс: {new_balance}"
            )

        # Логируем
        await db.add_event(...)

        # Обновляем статистику (проигрыш = bid)
        await db.update_user_stats(user_id, -user_bid, is_bankruptcy=(new_balance <= 0))

        return  # Не продолжаем обычную логику

    # ... обычная логика слотов ...
```

### Новый метод в Database (db.py)

```python
async def get_yesterday_total_won(self, chat_id: int, start_utc: str, end_utc: str) -> int:
    """
    Возвращает сумму всех выигрышей в чате за период.
    Используется для расчёта базовой величины ивента.
    Исключает heist_win чтобы не создавать обратную связь.
    """
    async with aiosqlite.connect(self.db_path) as db:
        async with db.execute("""
            SELECT COALESCE(SUM(amount), 0)
            FROM event_history
            WHERE chat_id = ?
            AND event_type IN ('win', 'happy_moment_win', 'dice_challenge_win')
            AND amount > 0
            AND created_at BETWEEN ? AND ?
        """, (chat_id, start_utc, end_utc)) as cursor:
            row = await cursor.fetchone()
            return row[0] if row else 0
```

## Граничные случаи

| Ситуация | Поведение |
|----------|-----------|
| Бот перезапущен во время ивента | Ивент теряется (не восстанавливается), банк аннулируется |
| Никто не крутил за весь ивент | Ивент завершается без выплаты, seed возвращается крупье |
| Только seed в банке, один спин | Игрок забирает seed × 0.7 + свой вклад × 0.7 |
| pot_cap пробит в Фазе 2 | Ничего — Фаза 2 уже активна, ивент закончится по таймеру |
| Баланс игрока < bid | Обычная логика: не может крутить |
| Игрок банкрот (balance ≤ 0) | Обычная логика: сообщение удаляется |
| Happy Moment + ивент одновременно | Множитель мига увеличивает виртуальный выигрыш → банк растёт быстрее |
| Два чата с разной экономикой | У каждого чата свой B и свой банк |
| Фаза 1 продлена, но pot так и < min_pot | Переход в Фазу 2 всё равно (продление однократное) |
| Hard cap (30 мин) сработал | Ивент завершается немедленно, выплата текущего банка |
